# Strategic scenario authoring

Use this workflow with a human author or an LLM facilitator. All work stays in the runner or a private staging directory; the vault is a read-only source, not a gameplay host.

1. Define the world, effective date, episode, player perspective, intended decisions and finite horizon. Identify organizations with actual agency, rather than turning every named population or institution into a faction.
2. Retrieve only relevant authorized source sections at pinned revisions. Distinguish facts available at opening from later retrospective history. Treat scenario quantities and inferred priorities as explicit exercise assumptions unless exact dated structured values have been verified.
3. Choose an existing supported mechanical family. For an economic episode use the Conflagration Mainlander Ingress spec as a structural example; for one-shot institutional commitments use Purge. Reuse the shapes, not their organizations, dates, quantities or political assumptions. Do not introduce new mechanics merely by adding JSON fields.
4. Specify each faction's own objectives, prioritized strategy, visible keys, reporting delays, permitted actions and independently controlled consent. Keep resource balances in initial state, not duplicated in profiles. All applicable profile identities and dates must match the scenario. Keep unknown context unresolved; do not assign zero as a substitute for unknown.
5. Return a candidate JSON object with exactly title, spec (ordinary version-1 scenario compiler specification), player_factions (explicit eligible actor IDs), and assumptions (nonempty list of reviewable statements). The candidate review supports fresh self-contained economic and institutional scenarios with explicit selectable factions. Preserve pinned evidence references when actually retrieved; numeric references require the existing source compiler rather than this rehearsal path.
6. Run `python -m age_runtime.core.scenario_authoring CANDIDATE.json`. The reviewer builds an isolated temporary draft inventory and invokes existing preparation diagnostics. Address blocked openings or missing identities by revising the candidate; do not weaken validators. The report does not register the candidate, approve assumptions or resolve source evidence.
7. After explicit author review, manually stage the ordinary spec and inventory entry in a private campaign, run the preparation command with authorized owners, rehearse contrasting outcomes, and use existing reviewed registration and distribution procedures. Never change review status solely because candidate checks passed.

Authoring instructions for the LLM: propose only the minimum necessary mechanics. Preserve independent consent, timing, resource conservation, uncertainty, and actor-specific knowledge. If the intended episode cannot be represented, state the missing mechanic and ask for a reviewed design rather than fabricate an effect. This workflow creates configurations, not arbitrary executable code.
